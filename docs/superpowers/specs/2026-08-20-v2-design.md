# Party Game v2 设计规格

> 状态：需求已与用户澄清确认（2026-08-20）。v1 已联机手测通过。
> 关联：v1 规格 `docs/superpowers/specs/2026-08-17-party-game-design.md`、v1 计划 `docs/superpowers/plans/2026-08-17-party-game.md`

## 背景与目标

v1 完成了核心玩法闭环（任务分配、状态机、事件判定、自定义 HUD、/party 命令）。手测反馈四个方向需要改进：地图、HUD 体验、判定、可配置性。v2 在不改变核心玩法（1 必做 + 2 禁忌、幸存者 +1、先到 5 分胜）的前提下解决这四块。

## 已确认的决策（2026-08-20 与用户澄清）

| 问题 | 决策 |
| --- | --- |
| 自建地图与程序生成的关系 | 地图列表里保留"程序生成房"作为内置选项；其余地图为自建（结构模板粘贴，不覆盖重建） |
| 自建地图圈定方式 | 站中心 + 半径：`/party map save <名字> <半径>` 保存模板；`/party setarena` 站中心点落地地图 |
| 出生点 | 红色羊毛标记，两类地图统一扫描：程序生成房由生成器在地板上放 8 块红羊毛（环形均匀分布）；自建地图由创作者放置。每回合重新随机分配，出生在羊毛上方 |
| 全灭处理 | 对局中全员出局 → 立即结束**本回合**：广播"全军覆没，本回合无人得分"，跳过剩余对局时间进入结算，结算后自动进入下一回合准备期；整场游戏继续 |
| 开发者通道 | 任务池继续用 config JSON + 写《任务维护指南》文档；触发类型已存在时改 JSON 即可，新触发类型才需代码 |
| /party config 持久化 | 写回 config/partygame.json |
| HUD 样式 | 右侧列表顶部加"阶段+倒计时"行与"第几轮"行；玩家行按分数排序着色；必做完成在行上标记 ✓ 并全服广播 |
| 出生点分配时机 | 每回合随机 |

## 一、地图系统

### 1.1 地图模型

- 地图 = 类型 + 模板/生成参数 + 出生点
  - `PROCEDURAL`：内置"程序生成房"，使用现有 ArenaGenerator（地板/围墙/按钮/压力板/装备箱）
  - `TEMPLATE`：自建地图，结构模板文件（含方块实体，即箱子内容随模板保存）
- 地图元数据持久化在 `config/partygame.json` 的 `maps` 数组：`{ "name", "type", "template"（模板文件相对路径）, "radius"（保存/扫描半径） }`
- 当前选中地图：`config/partygame.json` 的 `selectedMap` 字段

### 1.2 命令

- `/party map save <名字> <半径>`（管理员）：以玩家站立位置为中心，把半径内方块+方块实体保存为结构模板到 `run/config/partygame/maps/<名字>.nbt`，并登记到 maps 数组，随后自动选中
- `/party map list`：列出全部地图与当前选中
- `/party map remove <名字>`（管理员）：删除地图模板与登记
- `/party map choose <名字>`（管理员）：选中地图（内置"程序生成房"名字固定为 `procedural`）
- `/party setarena`（管理员，保留 v1 命令名）：记录中心点 = 玩家站位；立即落地一次当前地图（供玩家肉眼确认）；扫描场地内红色羊毛得到出生点列表，数量不足 `minPlayers` 时报错

### 1.3 落地与出生流程

- `beginRound()` 开始时重新落地当前地图：
  - PROCEDURAL → `ArenaGenerator.generate(...)`（v1 逻辑 + 新增：地板环形均匀放 8 块红色羊毛出生标记）
  - TEMPLATE → `StructureTemplate` 粘贴到以中心点对齐的位置（覆盖区域内方块，相当于"重贴一次恢复被破坏的方块"）
- 两类地图落地后统一重新扫描红色羊毛 → 出生点列表 → 每个存活参赛玩家随机分配一个（羊毛保留，玩家出生在羊毛上方 1 格）
- 自建地图的装备由创作者在搭建时放进箱子，程序不放装备；程序生成房保持 v1 自动放装备

### 1.4 技术要点（写代码前按老规矩核对 21.11.45 签名）

- `StructureTemplate` 的 save/load（NBT 读写）、`placeInWorld(ServerLevel, BlockPos, BlockPos, StructurePlaceSettings, RandomSource, int)`、`StructurePlaceSettings` 各 setter
- 羊毛判断：`Blocks.RED_WOOL`
- 扫描/粘贴范围：水平以中心 ± 半径；垂直以中心所在高度 ± 半径（柱形），保证有高低差的地图羊毛也能扫到

## 二、HUD 重构

### 2.1 右侧列表内容（从上到下）

1. 第几轮（"第 3 轮"）
2. 阶段 + 剩余时间倒计时（如"准备期 12s"、"对局 97s"、"结算 5s"；IDLE 时显示"等待开局"）
3. 你的必做任务：XXX（完成后追加 ✓）
4. 每个玩家一行（按分数降序）：
   - 名字（自己加粗或加"你"标识）、分数、当前禁忌文本（自己显示 ???）、剩余命数 ♥、必做完成标记 ✓（任何人的必做完成都显示）
   - 颜色按分数：0-1 白 / 2-3 黄 / 4 紫 / 5+ 金（沿用 v1）
   - 出局玩家显示"已出局"

### 2.2 网络包扩展

- `SyncStatesPayload` 增加字段：`phase`（字符串）、`countdownSeconds`（int）、`round`（int）、`myMustDo`（文本 + 是否完成）、玩家行增加 `mustDoDone`（bool）
- 发送时机沿用 v1 的刷新点，并新增：倒计时每秒变化 → 需要**每秒刷新**（或客户端本地每秒自减，服务端只发阶段切换）——实现选型在实施计划里定，倾向客户端本地倒数、服务端在阶段切换/状态变化时刷新，减少发包
- 必做完成广播：`GameManager.onTrigger` 完成必做时 `broadcast("§aXXX 完成了必做任务！")`（他人可见，便于针对）

## 三、判定优化

### 3.1 全灭立即结束本回合

- 在 `eliminate()` 末尾检查：若 `phase == PLAYING` 且所有玩家 `!isAlive()` → 广播"§c全军覆没！本回合无人得分" → 调用 `endRound()`（跳过剩余对局时间）
- `endRound()` 现有逻辑天然兼容：无存活玩家 → 无人加分 → 进入 SCORING → 结算后自动 `beginRound()` 进入下一回合
- 整场游戏继续（先到 5 分才结束）；无人得分时不可能触发胜利判定
- 触发路径覆盖：禁忌出局、死亡出局、掉线出局。掉线至全员离线的场景保留 v1 行为（强制回 IDLE，因为没人能继续玩）
- `eliminate()` 在 endRound 的超时循环里也会被调用，此时 phase 已是 SCORING，不会重复触发全灭判定

### 3.2 胜利结束与再开局（修复 v1 隐藏问题）

- `finishGame()` 宣布胜者后：`phase = IDLE`（而非 FINISHED）、清空 `states`（下次 /party start 是全新一局，分数清零）
- `startGame` 的"游戏已在进行中"检查保持不变（IDLE 才能开）
- `/party stop` 中途终止并清空 states（v1 行为不变）

## 四、配置命令与开发者通道

### 4.1 /party config（写回 config/partygame.json）

- `/party config show`：显示全部可调项当前值
- `/party config set <键> <值>`（管理员）：键为 `minPlayers`、`preparingSeconds`、`playingSeconds`、`scoringSeconds`、`targetScore`；改完写回配置文件
- 写回实现：`ModConfig` 增加 `save()`（把内存中的 root 序列化写回原路径）；新增 `setInt(key, value)` 辅助
- 阶段时长等对局中修改：下一回合生效（`enterPhase` 每次读取 config）

### 4.2 /party tasks（任务池启停，写回配置）

- `/party tasks list`：列出全部任务（id、类型、显示名、启用状态）
- `/party tasks enable <id>` / `/party tasks disable <id>`（管理员）：任务池 JSON 的每项加 `"enabled": true` 字段（缺省视为启用，兼容旧配置）；`TaskPool` 过滤未启用任务
- 分配器保护：启用禁忌 < 2 或必做 < 1 时 `/party start` 报错（现有"任务池不足"异常沿用）

### 4.3 开发者通道文档

- 新建 `docs/task-maintenance-guide.md`《任务维护指南》：
  - 任务 JSON 格式与字段说明（id/type/triggers/displayName/enabled）
  - 新增任务步骤（触发类型已存在：改 JSON + 重启；不存在：加 TriggerType 枚举 + 事件监听映射 + 文档登记）
  - 修改后验证方式（单人 /party start 跑一局）

## 五、验收标准（v2 手测清单扩展项）

- 地图：保存自建地图 → list 可见 → choose 后 setarena 能把地图粘贴进主世界 → 红色羊毛被识别为出生点 → 每回合随机分配且羊毛保留
- HUD：阶段倒计时与轮数正确、必做完成打 ✓ 且全服广播、自己禁忌 ??? 且命数正确、分数排序与颜色正确
- 判定：对局中全员出局 → "全军覆没，本回合无人得分" → 结算后自动进入下一回合；胜利后 /party start 是全新一局（分数清零）
- 配置：/party config set minPlayers 1 写回文件（重启后仍为 1）；/party tasks disable 后该任务不再被分配
- 回归：v1 全部清单项不破坏

## 六、风险与边界

- 结构模板 API 签名以 21.11.45 反编译 jar 核对为准（编译期可验证）
- 大半径地图粘贴/保存的耗时：默认半径 ≤ 31 无碍；超大半径属用户自担
- 模板内方块实体（箱子、告示牌）随模板保存粘贴；实体（生物）不保存
- 多人同地图同时粘贴无并发问题（服务器主线程顺序执行）
- 距离类任务（"不能靠近某人"等）仍不在 v2 范围（v1 后确定）
