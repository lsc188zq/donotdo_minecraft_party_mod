# 派对生存 mod 设计文档

- 日期：2026-08-17
- 状态：已获用户批准（含 3 处修订：一站定竞技场、装备箱抢装备、禁忌触发告知内容）
- 目标平台：Minecraft 1.21.11 + NeoForge 21.11.45，Java 21
- mod_id：`partygame`（如无异议，实施阶段按此注册）

## 1. 项目目标

一个多人派对玩法 mod：玩家聚集在竞技场内，每人随机获得 1 件必做任务和 2 件禁忌任务，在 3 分钟回合内完成必做、避免触犯禁忌、在 PVP 中存活。回合幸存者 +1 分，先到 5 分者获胜。

## 2. 玩法规则（已确认）

### 2.1 任务分配

- 每人每回合：1 件必做任务（**只有自己可见**）+ 2 件禁忌任务（**自己不可见，其他玩家可见**）。
- 其他玩家视角：每位玩家一次只显示 1 件禁忌；**第一件被触发后，第二件才激活并显示**（相当于两条命）。
- 分配约束：两件禁忌不重复；禁忌"不能攻击"不与必做"对玩家造成伤害"分给同一人。

### 2.2 出局与得分

- 出局条件（满足其一即出局）：
  1. 死亡（任何原因：PVP、摔落、环境伤害）
  2. 两件禁忌都被触发
  3. 回合超时时必做任务未完成
- 触发第一件禁忌：玩家收到提示，**告知触犯的具体内容**，并得知"剩余一条命"。
- 回合结束时未出局者 +1 分；先达到 5 分者获胜（可配置）。

### 2.3 PVP 与装备

- 原版战斗规则（武器、护甲、伤害机制）。
- 装备来源：竞技场内 4 个装备箱，**准备期（30s）内抢夺**；准备期禁止玩家间攻击。
- 死亡不掉落物品。

### 2.4 任务池（v1）

- 必做 5 种：按下按钮 / 压压力板 3 秒 / 对任意玩家造成一次伤害 / 吃一个食物 / 打开一个箱子。
- 禁忌 8 种：不能跳跃 / 不能疾跑 / 不能攻击任何玩家 / 不能打开箱子 / 不能破坏或放置方块 / 不能吃食物 / 不能在聊天发言 / 不能蹲下。
- 全部任务写在配置文件里，增删无需改代码（见第 6 节）。

## 3. 架构：集中式状态机

```
IDLE → PREPARING(30s) → PLAYING(180s) → SCORING(10s) → 有人≥5分? → 是：FINISHED(公告胜者) → IDLE
                                                          → 否：回到 PREPARING
```

模块划分：

- **GameManager**：状态机与回合流程，玩家状态（存活/出局/分数/任务），唯一的事实来源。
- **task 包**：`Task` 接口 + 13 个具体任务类 + `TaskRegistry`（按 id 注册）+ 任务分配器（含冲突约束）。
- **event 包**：NeoForge 事件监听器，把游戏事件转成任务判定信号；同时负责准备期禁攻击、死亡掉落控制。
- **arena 包**：竞技场生成器（坐标数学搭方块）。
- **ui 包**：计分板（fake-entry 技巧）、屏幕大字提示、聊天公告。
- **command 包**：`/party` 系列命令（Brigadier）。
- **config**：JSON 配置读取。

各模块不直接互相调用，统一经由 GameManager 的状态与接口通信；事件监听器是系统与 MC 世界之间的边界。

## 4. 一回合时间线

1. OP 站在想要的竞技场中心点，输入 `/party setarena` 记录中心点。
2. `/party start`（需 ≥2 名在线玩家）。
3. 系统生成竞技场（固定尺寸，见第 5 节）→ 传送全部玩家进场 → 清空背包。
4. 抽签分配任务（含冲突约束）。
5. **准备期 30s**：计分板显示所有其他玩家的当前禁忌；自己的必做任务用屏幕大字 + 聊天提示；玩家抢夺 4 个装备箱；**玩家间攻击被禁用**。
6. **对局 180s**：事件监听自动判定。触发第一件禁忌 → 告知内容 + "剩余一条命"，计分板上该玩家的禁忌切换显示为第二件；触发第二件 → 出局；死亡 → 出局（转旁观模式）；完成必做 → 仅自己可见的提示。
7. **结算 10s**：公告幸存者与分数榜；未出局者 +1 分。
8. 检查是否有人达到 5 分 → FINISHED（公告胜者，回 IDLE）或自动进入下一回合准备期。**下一回合所有玩家（含上一回合出局者）重新进场参与，分数保留。**

## 5. 竞技场

- 固定 31×31（可配置），以 `/party setarena` 记录点为中心生成。
- 石砖地板、3 格高围墙、无顶；无门，开局直接传送进场。
- 内容：4 个装备箱（内容从物品池随机：每箱 1 件武器 + 2 件护甲 + 4 个食物）、1 个墙上按钮、1 块地面压力板。
- 风险：生成会覆盖原位置方块且**不恢复**。`/party setarena` 执行前 OP 自行确认场地空旷。

## 6. 配置（JSON）

| 配置项 | 默认值 |
| --- | --- |
| 准备期时长 | 30s |
| 对局时长 | 180s |
| 结算时长 | 10s |
| 目标分数 | 5 |
| 任务池 | 必做 5 + 禁忌 8（含冲突规则） |
| 装备箱物品池 | 武器/护甲/食物 |
| 竞技场尺寸 | 31×31 |

## 7. 命令

| 命令 | 作用 | 权限 |
| --- | --- | --- |
| `/party setarena` | 站中心点记录竞技场位置 | OP |
| `/party start` | 开始游戏 | OP |
| `/party stop` | 强制终止游戏回 IDLE | OP |
| `/party score` | 查看分数 | 所有玩家 |

## 8. UI

- 右侧计分板：按**分数降序**排列；每行 `[玩家名] [当前禁忌] [剩余命数]`。
- 文字颜色按分数：0-1 白 / 2-3 黄 / 4 紫 / 5+ 金。
- 自己的行：禁忌显示 `???`（自己不可见），剩余命数可见。
- 技术说明：原版计分板是服务器全局状态，无法按玩家区分显示（自己的行会暴露给自己的禁忌），故采用自定义客户端 HUD——服务端为每位玩家下发个性化视图，客户端渲染仿侧边栏列表。玩家上限 8 人。

## 9. 边界情况

- 掉线 = 出局；不支持中途加入（可旁观）；对局中全员掉线 → 强制回 IDLE。
- 背包清空 + 3 格围墙 + 无物品来源 → 玩家无法逃出竞技场，无需越界检测。
- 任务判定只在对局阶段生效；准备期攻击被禁用，不存在误判窗口。

## 10. 测试与验证

- **JUnit**：任务分配约束、分数计算等纯 Java 逻辑。
- **GameTest**：竞技场结构断言（地板/围墙/按钮/压力板/箱子坐标）。
- **集成手测**：本地专用服务器 + 双客户端，按测试清单逐项验证完整流程。
- 修复流程：先复现 → 修复 → 验证（附验证方式与结果）。
