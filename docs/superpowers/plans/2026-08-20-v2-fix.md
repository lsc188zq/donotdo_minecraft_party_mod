# Party Game v2 修复方案

**Goal:** 修复 v2 手测发现的 4 个问题：HUD 不显示、换地图时旧红羊毛残留、缺少方块破坏防护、游戏时间未设为白天；并按用户要求增加"结算期重置地图"。

**Architecture:** 不改动 v2 现有架构。HUD 问题先取证定位再修复；羊毛清理与结算期重置落在 MapManager/GameManager；破坏防护落在 GameEventListeners。

**Spec:** `docs/superpowers/specs/2026-08-20-v2-design.md`（设计不变，本方案为缺陷修复）

## 背景：问题清单（来自 v2 手测反馈）

1. **HUD 不显示**：v1 起就未显示（右侧无轮数/倒计时/必做/玩家列表）
2. **旧红羊毛残留**：`/party setarena` 落地新地图时，原地块附近的旧红色羊毛未清除
3. **无破坏防护**：游戏期间玩家可破坏竞技场方块
4. **时间未设白天**：游戏期间可能到夜晚
5. （新增需求）**结算期重置地图**：修复对局中被破坏的方块

### Task 1: HUD 定位与修复（先取证，后修复）

**已完成的静态排查（结论：整条链路按 21.11.45 源码验证均正确）：**

- payload 注册：`playToClient(type, codec, handler)` 会把客户端 handler 写入 `CLIENTBOUND_HANDLERS`（源码核实），缺失会直接崩客户端，而用户日志无崩溃 → 注册成功
- 客户端分发：打补丁后的 `ClientCommonPacketListenerImpl` 确认会调 `ClientNetworkRegistry.handleModdedPayload`（字节码核实）
- 单人模式网络协商：用户 debug 日志中 `NetworkFilters` 注入成功 = payload setup 协商完成；官方文档明确 memory connection（单人/局域网）同样序列化处理
- 渲染事件：`RenderGuiEvent.Post` 在主事件总线、仅客户端触发；`GameEventListeners` 用相同的"静态方法 + Class 注册"模式且工作正常
- 用户日志：无"Unknown custom packet payload"警告、无"missing client-side handlers"异常、无任何 ERROR

**因此根因无法静态确定，分两步取证：**

- [x] **阶段 A（零代码，用户执行）**：联机对照实验——结论：与服务器模式无关（单人与联机均不显示）
- [x] **阶段 B（插桩诊断）**：4 个组件边界日志显示注册/发包/收包/渲染事件全部正常，故障锁定在"渲染绘制"环节
- [x] **修复（根因）**：`drawString` 的颜色参数是 ARGB 格式，前 8 位为 alpha。HUD 全部颜色值（`0xFFFFFF`、`0xFFD700`、`0xAA00AA`、`0xFFFF00`）都缺少 `0xFF` alpha 前綴 → 文字以**全透明**绘制，v1 起就不可见。已全部改为 `0xFFxxxxxx` 形式
- [x] **验证**：`./gradlew compileJava test` 通过；视觉效果待用户手测确认

**范围：** `PartyHud` 颜色值修正；诊断日志已全部移除。

**验收标准：** 对局中 HUD 右侧显示"第 N 轮 / 阶段+倒计时 / 你的必做 / 玩家列表"，倒计时每秒递减。

### Task 2: 落地地图前清空区域全部方块与掉落物

**方案（用户已调整为"所有方块"+ 掉落物）：** `MapManager.land()` 开头，在生成/粘贴地图**之前**，把中心 ±扫描半径立方范围内的**所有方块**替换为空气、**区域内掉落物全部清除**，再执行原落地逻辑。

**方案（用户已调整为"所有方块"）：** `MapManager.land()` 开头，在生成/粘贴地图**之前**，把中心 ±扫描半径立方范围内的**所有方块**替换为空气，再执行原落地逻辑。

- 程序生成房：清空后生成器重建地板/围墙/羊毛/箱子等
- 模板地图：清空后粘贴（模板连同空气一起覆盖，区域内最终与模板一致）
- 覆盖三条路径：`/party setarena`、每回合 `beginRound`、结算期重置（Task 5）
- 清空区域 = 该地图的扫描半径（与 `scanSpawns` 一致，含 Y 轴 ±半径的整立方）

**范围：** 仅 `MapManager`。**风险：** 区域内地表/地下方块被全部清空（竞技场下方形成空腔，地板受保护不会破坏，不影响玩法）；清空为大范围方块更新，超大半径（如 100）的自建地图落地会有数秒耗时（与扫描同量级）。**验收标准：** setarena 落地新地图后原区域旧方块（含旧羊毛/旧墙/旧地板）全部消失，出生点数量正确。

### Task 3: 方块破坏防护（保护名单制 + JSON 可配置）

**方案（用户已确认）：** 游戏进行期间（phase ≠ IDLE，含准备/对局/结算），破坏"受保护方块"的事件被取消（方块不变），其余方块可正常破坏。**放置不限制**（围墙封口，允许玩家放置）。

**受保护方块清单（用户已确认）：**

| 方块 | 判定方式 | 理由 |
| --- | --- | --- |
| 石砖（stone_bricks） | JSON 名单 | 程序生成房的地板与围墙（两者同类型，一并覆盖） |
| 红色羊毛（red_wool） | JSON 名单 | 出生点 |
| 箱子（chest） | JSON 名单 | 准备期装备来源 |
| 按钮（任意 ButtonBlock） | 代码类型判定 | 必做任务机制（所有木质/石质按钮自动覆盖） |
| 压力板（任意压力板） | 代码类型判定 | STAND_PLATE_3S 任务机制（所有材质自动覆盖） |

**JSON 可配置：** 配置新增 `"protectedBlocks": ["minecraft:stone_bricks", "minecraft:red_wool", "minecraft:chest"]`，维护者可随时添加方块 id，无需改代码。加载时解析为方块集合，**id 写错在启动时直接报错**（与任务池配置的 fail-fast 风格一致）。按钮/压力板因涉及"任意材质"语义，保留代码类型判定，不放入 JSON。

- **与任务兼容**：对局中尝试破坏受保护方块时，`no_break_place` 任务的触发判定**照常执行**（人会受罚、方块不破）
- 模板地图的普通建材不受保护（按"其他可以破坏"）；模板内的羊毛/按钮/压力板仍受保护
- 结算期地图重置（Task 5）兜底修复其余破坏

**范围：** `GameEventListeners.onBreak`、`ModConfig`（protectedBlocks 解析）、`DefaultConfig`。

**验证说明：** `protectedBlocks()` 返回 MC 方块对象，而本项目测试类路径只有 JUnit + Gson（无 MC 类），无法单元测试——按项目惯例以编译通过 + 游戏内手测验证（手测清单补充）。

**风险：** 石砖被保护意味着模板地图若用石砖做装饰也受保护（可接受）。**验收标准：** 对局中敲地板/围墙/按钮/羊毛/箱子/压力板无破坏反应；其他方块可破坏；no_break_place 玩家尝试破坏受保护方块仍受惩罚。

### Task 4: 游戏时间设为白天

**方案：** `beginRound()` 开局时把世界时间设为正午（6000）。每回合设置一次；一回合（准备 30s + 对局 180s）内时间不会走到夜晚，无需冻结时间。实现前按项目惯例用 javap 核对 21.11.45 的 `ServerLevel.setDayTime`/`setTimeOfDay` 签名。

**范围：** 仅 `GameManager.beginRound`。**风险：** 低。**验收标准：** 开局与每回合均为白天，整局不会入夜。

---

### Task 5: 结算期重置地图

**方案：** `endRound()` 进入结算（SCORING）前调用 `MapManager.land()` 重新落地当前地图，对局中被破坏的方块在结算期即恢复。`beginRound` 的落地保留（首回合落地 + 每回合开始时兜底）。

**范围：** 仅 `GameManager.endRound`。**风险：** 每回合多一次地图重建开销（量级几十毫秒，手测观察卡顿即可）；结算期玩家为旁观者，重建不影响对局。**验收标准：** 结算期开始时竞技场恢复完整（被破坏的方块回来、箱子重新生成）。

### Task 6: 竞技场火把照明

**方案（用户已确认）：** 程序生成房内墙每隔 4 格挂一支墙火把（高度 2），照亮场地，夜晚也不至于全黑。模板地图的照明由建图者负责（模板会保存火把）。

**范围：** 仅 `ArenaGenerator.generate`。**风险：** 低（火把可被破坏，下回合/结算期重生）。**验收标准：** 程序生成房四面内墙有规律分布的火把，场地内无明显黑暗区域。
